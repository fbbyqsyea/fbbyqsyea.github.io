# 成本与性能优化

## 成本控制

### 关键参数

| 参数 | 作用 | 建议值 |
|------|------|-------|
| `--max-budget-usd` | API 花费上限 | 按任务复杂度设定 |
| `--max-turns` | 循环次数上限 | 简单任务 3-5，复杂任务 10-15 |
| `--effort` | 推理深度 | 低复杂度用 `low`，高复杂度用 `high` |
| `--model` | 模型选择 | 简单任务用 `haiku`，复杂任务用 `opus` |

### 最低成本注意

`--max-budget-usd` 的最低值约为 $0.05 — 系统提示缓存创建本身就需要这个金额。设置更低会立即报错。

## 性能优化技巧

1. **Print 模式使用 `--max-turns`** — 防止无限循环和成本失控。简单任务从 5 开始，复杂任务 10。

2. **使用 `--max-budget-usd` 设置成本上限** — 注意最低 $0.05 的缓存创建成本。

3. **简单任务使用 `--effort low`** — 更快、更便宜。复杂推理使用 `high` 或 `max`。

4. **CI/脚本中使用 `--bare`** — 跳过插件/hook 发现开销，启动最快。

5. **使用 `--allowedTools` 限制权限** — 仅允许任务真正需要的工具。例如代码审查只给 `Read`。

6. **交互会话中及时使用 `/compact`** — 当上下文变大时压缩，保持精度。

7. **管道输入替代文件读取** — 当你只需要分析已知内容时，用管道比让 Claude 自己读文件更高效。

8. **简单任务使用 `--model haiku`** — 更便宜。复杂多步工作使用 `--model opus`。

9. **Print 模式使用 `--fallback-model haiku`** — 优雅处理模型过载。

10. **不同任务开启新会话** — 会话持续 5 小时；新鲜上下文比累积历史更高效。

11. **CI 中使用 `--no-session-persistence`** — 避免在磁盘上累积保存的会话。

## 上下文窗口管理

| 使用率 | 精度影响 | 行动 |
|--------|---------|------|
| < 70% | 正常 | 继续 |
| 70-85% | 精度开始下降 | 考虑 `/compact` |
| > 85% | 幻觉风险显著增加 | 必须 `/compact` 或 `/clear` |

## 模型选择决策树

```
任务复杂度？
├── 简单（格式转换、查找替换）→ haiku + effort low
├── 中等（代码审查、Bug 修复）→ sonnet + effort medium
└── 复杂（架构设计、多步推理）→ opus + effort high/max
```

## 缓存利用

Anthropic 的 Prompt Caching 可以显著降低成本：

| 场景 | 缓存命中率 | 成本节省 |
|------|-----------|---------|
| 相同 CLAUDE.md 的项目 | 高 | 50-80% |
| 相同提示的批量任务 | 高 | 50-80% |
| 每次不同的提示 | 低 | 0-10% |

最大化缓存命中：

- 保持 CLAUDE.md 稳定
- 使用相同的系统提示
- 批量处理相似任务
